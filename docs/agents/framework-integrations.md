# React and Vue integrations

Framework integrations call `mask()` on a real input and reuse the same controller. They must not duplicate masking or editing behavior. The package publishes them from `secret-input/react` and `secret-input/vue`; the root entry has no framework dependency.

The React 19 component renders one native input and gives callers the masked `SecretInput` through `ref`. Its `value`, `defaultValue`, and `redacted` props synchronize controller state. Accepting the current controlled value preserves both undo and redo history. `onInput(value, event)` reports each accepted edit; `onChange(value, event)` reports the native blur-time commit. The second argument retains the native presentation target, so never imply that `event.currentTarget.value` is authoritative or pass the actual value through the native `value` prop.

The Vue adapter is an SFC written with `<script setup>`. It implements `modelValue` / `update:modelValue`, plus `defaultValue` and `redacted`; accepting the current model value preserves both undo and redo history. It renders one native input and forwards undeclared attributes and listeners; declared `type` and `value` props are consumed rather than forwarded because those remain controller-owned presentation details. Native `input` and `change` are re-emitted from listeners installed after `mask()`, so rejected browser mutations cannot reach Vue callbacks first.

Both adapters preserve native name-based form participation, attributes, classes, and styles. React and Vue remain optional peers. Their `input` and `change` callbacks consistently receive `(value, event)`, while Vue `v-model` uses `update:modelValue`. Keep the three input accessors, native core events, and `mask()` stable; add adapter API only when it provides concrete framework value.

Server output remains the same `input[type="text"]` used by the client, with autofill and text-service defaults plus one bullet per initial-value grapheme. Plaintext is never the native value during SSR, including when `redacted` is false; reveal happens only after attachment. Never render a temporary password input because browsers and extensions can classify or fill it before hydration, and replacing it later cannot undo that observation. Hydration attaches `mask()` and discards any pre-attachment DOM mutation because it cannot be distinguished reliably from autofill.

Vite+ packages the SFC through tsdown and `unplugin-vue`. Run `vpr check` so the normal Vite+ checks and `vue-tsc --noEmit` both execute. The pinned `typescript-native-bridge` package preserves the TypeScript API required by Vue tooling while running the TypeScript 7 tsgo checker. Keep its exact version and the pnpm workspace `typescript` override aligned; this is a development-tool dependency, not part of the published runtime.
