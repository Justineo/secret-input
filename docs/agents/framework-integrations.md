# React and Vue integrations

Form-library integration uses component values, callbacks/model, and application errors. Raw-DOM collectors and exact native event emulation are outside the contract; cover capabilities, not every library's native-input adapter.

Framework integrations call `createSecretInput()` on a real input and keep the returned controller. They must not duplicate masking or editing behavior. The package publishes them from `secret-input/react` and `secret-input/vue`; the root entry has no framework dependency.

React 19 uses `value` / `onChange(value: string)` for controlled input and `defaultValue` for uncontrolled input. Types reject simultaneous value/defaultValue props. onChange is optional; an editable controlled owner uses it to update state. readOnly, disabled, and other ordinary input attributes inherit their native types. The pending readonly guard is removed after attachment, respecting the author's readOnly prop; later changes use ordinary prop synchronization. Keep the mode fixed for the lifetime of the component. There is no confirmation-time callback or onCommit API. The adapter maps accepted core input to onChange immediately; Enter and blur do not generate another React value callback.

The React value callback receives only the actual string, following value-based component APIs such as React Aria TextField. Callers can pass a state setter directly. Do not make consumers extract business values from a synthetic event or introduce an onValueChange alias. Ordinary onInput(event), focus, blur, and keyboard handlers retain their React event roles. Native input.value remains presentation; the ref is available for imperative native operations. Do not fabricate DOM targets, change the value getter, or access React's private tracker. This is a component value contract, not a claim to reproduce every native input event.

The parent is authoritative in React controlled mode. After a callback, accepting the same value preserves selection and history; rejecting it restores the committed parent value. Only committed renders update the restoration value, and queued work must not act on an unmounted/replaced input. The controller's reset baseline follows the controlled value, matching React's controlled text-input behavior. Uncontrolled defaults can change the reset baseline without replacing the user's current edit. Reset remains cancelable and does not emit a value callback. Parent onReset handlers can reset controlled state explicitly.

The Vue adapter is an SFC written with `<script setup>` and `defineModel<string>()`, without a default model value that could diverge from an undefined parent. `modelValue` / `update:modelValue` is the only value API: no Vue value/defaultValue aliases. Write the model to report an accepted edit, then synchronize after Vue's update flush. Without a bound parent model, defineModel supplies local state. Initialize and reset by updating the model; native reset keeps the current model value. An empty/undefined model is presented as an empty string.

Vue exposes a read-only component-ref property `input` pointing to the native input, or undefined when detached. Its native `input` and `change` observers receive only the DOM event. They are re-emitted from listeners installed after `createSecretInput()`, so rejected browser mutations cannot reach ordinary Vue callbacks first. The forbidden value/defaultValue presentation overrides are consumed rather than forwarded to the DOM. Neither adapter exposes a type prop; the template/render function fixes the native type to text. The revealed boolean defaults to false in both adapters. Declared native observers are not another model synchronization protocol.

Both adapters preserve native name-based form participation, attributes, classes, styles, and accessible relationships. React and Vue remain optional peers. Framework users update values and redaction through props/model; direct ref writes compete with controlled ownership. The ref provides native focus, selection, and constraint-validation methods without adding component aliases. Use read-only controller state and synchronous update patches; keep native core events and the plain input ref.

React keeps its initial defaultValue markup stable; Vue binds the initial mask with `:value.attr`. Once the controller takes over, unrelated renders must not write a stale live DOM value or reset selection. Keep initial SSR markup separate from the current editing value. Callback-ref changes and React Strict Mode must not reinitialize the controller or duplicate callbacks.

Server output remains the same `input[type="text"]` used by the client, with autofill and text-service defaults plus one bullet per initial-value grapheme. Plaintext is never the native value during SSR, including when revealed is true; reveal happens only after attachment. SSR also sets readonly until controller attachment. React releases that guard through committed ready state; Vue restores the readonly prop synchronously in its input ref and keeps its template in sync. JS loading failure leaves the field readonly. Hydration discards pre-attachment script/browser writes, which cannot reliably be distinguished from autofill; user editing is unavailable during this window. This is an autofill and initialization decision, not a DOM confidentiality requirement. CSS masking remains a comparison alternative because it has triggered password suggestions in Safari.

Vite+ packages the SFC through tsdown and unplugin-vue. Run `pnpm check` for normal checks and vue-tsc, then build, publint, and `pnpm check:package-types`. Published Vue declarations refer to the public vue peer rather than undeclared internal packages; the package build rewrites those generated type imports and a strict consumer fixture verifies them. Keep the pinned TypeScript bridge and workspace override aligned. Browser tests prebundle React, React DOM, and Vue together to avoid dependency-optimization reloads introducing multiple React instances. Test adapters with real typing, Enter submission, reset-button activation/cancellation, and unrelated renders as well as fast unit tests.

The full design rationale and migration rules are in [public API design](../public-api-design.md).

Validation rules are explicit controller options. React consumes pattern/minLength/maxLength/required and Vue consumes pattern/minlength/maxlength/required; both pass them directly to controller.update(), including undefined to remove rules. Both also consume the validationMessages map for string/function rule-message overrides and the customValidity string for application errors; neither is forwarded to the DOM or emitted in SSR markup. Formatters do not run during SSR. Vue snapshots reactive map entries in its options getter so entry changes trigger synchronization. Only requiredness is mirrored onto the input. Never render delegated data attributes or native pattern/minlength/maxlength on the presentation input. Rule updates preserve node/value/selection/history and callback count. React synchronizes in its committed layout effect; Vue synchronizes model and rule props after its update flush and after input callbacks. Neither adapter needs attribute observation or custom-validity interception.

React refs expose HTMLInputElement; Vue component refs expose the plain HTMLInputElement as input. Framework model/props own secret state; the refs are for native interaction. Application errors use the customValidity prop and persist through synchronization, reset, and unrelated renders until the prop is cleared or removed. Core owns the native custom-validity slot. Application callbacks own error expiration and async request revisions; do not make framework renders clear an error implicitly. Vue uses one options getter for creation, synchronization, and reactive dependencies so the mappings cannot drift.
