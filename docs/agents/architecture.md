# Architecture and value model

The product goal is to avoid unwanted autofill and password suggestions while providing useful input capabilities. DOM plaintext isolation and complete native-input parity are not goals. The current controller separates application state from presentation to reject unwanted browser writes; evaluate alternative implementations by autofill behavior and input usability.

`createSecretInput()` creates one closure-backed `SecretInputController` per native `input[type="text"]` and returns that controller. Repeated creation returns the existing controller without reinitialization; `controller.update()` is the explicit update path. No wrapper or Shadow DOM is created. The native element remains the styling, focus, selection, label, accessibility, form, and event surface.

Keep the public API focused on ordinary secret entry. Prioritize correct typing, paste, deletion, reveal, undo/redo, form submission, and framework synchronization. Add hooks or lifecycle events only for demonstrated application needs; a difference from native event behavior alone does not justify a new API. Native `beforeinput` is used internally to intercept browser writes: an earlier capture listener can cancel it, but later listeners cannot undo an edit the controller has already applied.

The actual string lives in the controller closure. Its public object has read-only input, value, defaultValue, and revealed properties plus update(options). The native element has no secret-state extensions. A WeakMap associates inputs with controllers for form handling and idempotent creation. Controller value is authoritative; defaultValue is the form-reset baseline; input.value is presentation. revealed defaults to false, producing one bullet per grapheme. Only an explicit revealed update exposes plaintext. Never reconstruct secrets from input.value or override its native property.

Update applies one synchronous patch: omitted keys stay unchanged, undefined clears settings, and all changes finish before returning. Validate length configuration before mutating anything. Different actual values clear history/composition; same-value synchronization preserves them. Reveal-only changes preserve the logical selection and history. Rule-only and default-value changes preserve editing state. Refresh form bindings on update and render the final state once.

Cancelable `beforeinput` operations are intercepted before the browser mutates `input.value`. The controller applies the operation to secret state, renders the selected presentation, and dispatches `input` on the same native element. Autofill-like replacements and unrecognized mutations restore that presentation without updating the secret. Updating `revealed` is a quiet presentation change: it preserves the logical grapheme selection and does not alter value or history.

Selections are represented internally as grapheme indices. Mask offsets already have that shape; revealed DOM selections use UTF-16 offsets and are translated at the controller boundary.

The value remains the supplied JavaScript string without Unicode normalization or an ASCII restriction; only CR/LF are removed to match native single-line value sanitization. Graphemes are an editing coordinate, not the value format. This intentionally renders one bullet per user-perceived character so the masked text surface cannot place ordinary edits inside an emoji or combining sequence. Native selection APIs and `maxlength` are defined in UTF-16 code units, so revealed selections are translated and length limits count the actual string's code units while accepting only complete graphemes.

`formdata` projects actual values for standard submission. Locate managed entries by counting successful native inputs, textarea values, selected enabled options, and file entries in control order. Replace only managed entries and preserve the browser's original ordinary values, files, and global entry order. Do not reproduce value serialization. Submitter names, dirname companion names, and form-associated custom-element names must be distinct from managed names; those entries cannot be attributed reliably from a formdata event. Earlier listeners must not rewrite managed-name entries. If entry counts disagree, leave that name untouched rather than delete unrelated data. Observers that need projected values run after the controller or read the completed FormData.

Form handlers are registered on the owner document, current root, and current form, with each event processed once. This covers detached forms and non-composed events inside shadow roots. Use realm-independent form detection so iframe and adopted inputs participate. Registration refreshes on focus and controller updates; call `controller.update({})` after moving an input to a new document or shadow root before submitting without focus. Reset waits for dispatch and the browser’s own reset to finish so later listeners can cancel it. Scripted `form.reset()` settles in a microtask. Native reset-button activation can run microtasks between listeners, so if dispatch is still active the controller defers to the next task before checking cancellation and restoring secret state.

Cache segmentation for the authoritative value and reuse the last rendered segmentation for revealed selection mapping. Re-segment splice results before calculating the caret: inserted combining marks, ZWJ sequences, and regional indicators may merge with surrounding graphemes. Preserve selection direction when changing presentation. Keep these coordinate conversions in `graphemes.ts`.

Pending transfer metadata belongs only to a matching, uncanceled paste/drop event. Metadata expires in a microtask after synthetic dispatch. If native dispatch is still active at that checkpoint, defer expiration to the next task so the browser can perform its default action and dispatch `input`. Canceled edits also retain their rendered logical selection for the same short input opportunity. If a keyboard mutates the DOM despite cancellation, the matching native input restores that selection without repeating the edit or breaking its history group. Navigation, focus changes, a different value/reveal update, another input operation, and expiration invalidate the old opportunity. Application callbacks may change the selection or replace the pending operation. A later `beforeinput` supplies fresh edit metadata; a subsequent native `input` must match its input type. Match controller-generated events by object identity, not a boolean dispatch flag, so nested unrelated events are still filtered. Filter native input/change at the target capture phase before ordinary target listeners.

History entries contain explicit before/after value and selection snapshots. An open contiguous group updates only its after snapshot; traversal moves entries between two stacks and restores the appropriate snapshot. Never rewrite the before snapshot to accumulate deletion ranges or sample selections at undo/redo time. Complete history and state changes before dispatching the accepted input event. The grouping, composition, reset, and event contracts are detailed in `platform-and-input.md`.

Validation derives messages in validation.ts from explicit options. Requiredness is mirrored onto the visible input; pattern/minLength/maxLength remain in controller state. Remove existing native pattern/minlength/maxlength attributes during creation without adopting them. Do not migrate rules, observe DOM attributes, or override setCustomValidity. Compare actual UTF-16 length directly. A lazy detached password input evaluates native patterns; length failures use explicit English defaults. validationMessages maps valueMissing/patternMismatch/tooShort/tooLong to strings or synchronous formatters. Empty or undefined overrides/results and formatter exceptions preserve the default failure. A formatter exception is treated as unavailable wording and does not interrupt initialization, edits, synchronization, history, or reset. Required formatters can obtain native default wording from an empty probe; length-only checks never create or write one. Clear probe.value in finally. Cache default failures by actual value, rules, requiredness, whether the required formatter needs native wording, title, lang, and ownerDocument, and recreate the probe when its document changes. Resolve the active message override separately so formatter closures refresh on each synchronization without repeating unchanged native checks. Formatters receive failure type, default wording, UTF-16 value length, and rule parameters, never the secret. Keep valueMissing native; derived failures use customError without fabricated native flags.

Store customValidity in the controller as an independent application message. Every render projects that message when nonempty, otherwise the derived result, by calling native setCustomValidity. Application messages persist until an explicit empty string or undefined clears them, including across edits, history, reveal, reset, and unrelated renders. Clearing one exposes any remaining rule error. Native method calls are never intercepted, but direct writes are not a second managed error source. Applications own expiration and async request revisions. Validate actual edits before public input events; update({}) still repairs presentation and refreshes form bindings without forcing unchanged rule computation.
