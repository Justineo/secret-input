Autocomplete off

Type
password
Setup
autocomplete="off"
Why use it
Uses the HTML autofill opt-out to ask the browser not to remember or fill the field, while keeping native password masking.
Limitations
Browsers deliberately ignore this hint for login-like fields. In our tests, Chrome, Edge, and Firefox autofill anyway. Safari shows its password picker on focus.

New-password

Type
password
Setup
autocomplete="new-password"
Why use it
Repurposes the new-password hint, intended for sign-up and password changes, to avoid inserting an existing password.
Limitations
It prevents automatic fill in our tests, but still identifies a password field. Focusing the fields can trigger password suggestions or password generation, interrupting entry even though this form is not creating a password.

CSS masking

Type
text
Setup
-webkit-text-security: disc
Why use it
Uses a text input to avoid password-field heuristics, then hides its characters with CSS masking.
Limitations
This nonstandard property only changes painting. Plaintext remains in the DOM and accessibility APIs. Safari still shows autofill UI, and IME behavior varies by browser.

Secret Input

Type
text
Setup
mask(input)
Why use it
Keeps the real value in controller state and puts bullets in a text input. Browser-written values cannot overwrite the application’s secret. Text inputs and autofill opt-out hints also reduce irrelevant password UI.
Limitations
Keyboard undo/redo and IME commits are supported. History grouping, native menu support, and IME suppression can differ from native password inputs. The accessible value is masked, with text-field semantics. Typing echo depends on assistive technology and user settings. Behavior details.
